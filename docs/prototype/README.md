# 轮次轨迹 · v0.9 重设计原型

> Figma 页面：`重设计原型 v0.9`（本地文件，2026-11-06）
> 预览图：本目录下 `1-01…` ~ `7-07…` 共 7 张 PNG（2x）。
> 原型只做信息层级与交互形态的评审，不对应最终实现；示例数据为示意。

## 为什么重做

对照现有实现（`src/client/TrailTab.tsx` + `styles.ts`）与三张实机截图，问题集中在三处：

1. **详情把头等大事塞进了 400px 的窄栏**：参数以格式化 JSON 原样展开，249 字符的 bash 命令只能横向滚动（截图 2/3）；`参数 / 结果 / 原始` 三个页签语义重叠，复制、放大、定位入口分散。
2. **列表缺少阅读层次**：208 个步骤平铺，行内「工具名 + 参数」互相挤压；轮次头只有编号与步数，看不出「这一轮到底发生了什么」。
3. **边角状态缺失**：并行组、失败行、截断、错误、空态没有统一表达，定位/复制都埋在 hover 里。

## 设计原则

| # | 原则 | 落点 |
|---|---|---|
| 01 | 描述先于命令 | 行内先读人话（工具 + 描述 / 文件名），原始参数按需展开 |
| 02 | 命令必须可读 | 按 `&&` / `;` 分段、软换行、语法高亮；杜绝横向滚动 |
| 03 | 分层而非并列 | 摘要 → 结果 → 参数 → 原始，默认落在最有用的一层 |
| 04 | 状态常驻 | 成功/失败、耗时、完整度、seq 始终可见 |
| 05 | 键盘优先 | ⌘F 搜索、⌘⇧O 放大、↑↓ 切步、⌘C 复制 |
| 06 | 语义准确 | 并行调用是同一助手步骤的兄弟节点，不缩进、不做子级；只用 `∥ 分组条` 标注归属 |
| 07 | 结构化参数 | MCP 等 JSON 工具不摆原始 JSON：服务 / 工具 / 参数键值表 / 结果分段呈现 |

## 落地建议（下一步）

1. `styles.ts`：把 `ttl-row` 拆成 32px 时间线行（图标 16 + 描述单行 + 右侧状态），新增 `ttl-band` 详情卡与 `ttl-code` 命令块；token 直接复用上表。
2. `tool-summary.ts`：参数摘要改为「描述优先」，`bash` 命令按 `&&`/`;` 预分段并输出 token 流，供高亮渲染；MCP 走 `splitMcpName` + 参数启发式摘要（如 `download_assets · PNG ×5`），细节放到详情参数表。
3. `TrailTab.tsx`：详情页签顺序改为 `摘要 / 结果 / 参数 / 原始`，`原始` 收进「⋯」菜单；补搜索框与会话概览。
4. `ZoomOverlay.tsx`：改为 260px 步骤大纲 + 宽版阅读区，保留 `↑↓ / Esc / ⌘F`。
5. 状态：骨架屏、空、失败、截断统一为 `EmptyState` 组件；长值默认折叠阈值 4 行。
